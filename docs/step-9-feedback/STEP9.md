# 第 9 步：资讯有用性与纠错反馈

## 目标

让用户能够表达一条简报是否帮助了产品判断，并为事实、链接或表述错误提供真正可送达的纠错入口。

## 实现

- 每条详情页提供“有帮助”和“帮助不大”两个互斥选项。
- 评价结果以资讯 ID 为键保存在当前浏览器 `localStorage`。
- 用户可以重新选择，界面通过 `aria-pressed` 和选中样式同步状态。
- 页面明确说明有用性反馈没有上传，避免制造虚假反馈闭环。
- “提交纠错”打开项目 GitHub Issue，新建页面预填资讯标题、来源、原文和资讯 ID。
- 纠错内容进入真实、公开且可追踪的处理队列。

## 验收标准

- 选择反馈后立即显示确认状态。
- 刷新后仍能看到此前选择，并可修改。
- 两个评价选项不能同时处于选中状态。
- 纠错入口携带足够上下文，不要求用户重复填写资讯信息。
- 所有反馈控件均可使用键盘操作。

## 数据边界

有用性评价只是本地产品原型数据，不用于全站统计。纠错内容仅在用户主动进入 GitHub 并提交 Issue 后才会发送。
