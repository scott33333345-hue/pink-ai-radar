# Pink AI Radar 信息架构 V1

确定日期：2026-10-17（Asia/Shanghai）  
定位依据：`docs/positioning/POSITIONING.md`  
设计目标：让中文产品从业者在 5 分钟内完成“知道重点—判断影响—决定行动”。

## 1. 当前结构问题

当前首页顺序是：首屏 → 全部资讯 → 信源矩阵 → 核验方法 → 页脚。

主要问题：

1. 首屏强调“7 条”和“资讯精选”，没有突出“对产品工作有什么帮助”。
2. 所有新闻几乎平级，用户仍要自行判断最重要的一条。
3. 筛选项混合地区与主题两个维度。
4. “信源矩阵”和“核验方法”内容存在重复，且出现在用户完成阅读之后。
5. 订阅按钮是全局主要操作，但订阅目前只是演示，优先级与真实能力不匹配。
6. 页面没有历史入口、收藏入口、项目说明或明确的反馈出口。

## 2. 新版信息架构原则

1. **先价值，后内容**：用户先知道网站能帮自己做什么。
2. **先重点，后完整列表**：先给一条今日必读，再让用户扫描其他内容。
3. **判断靠近事实**：产品影响与行动建议必须跟新闻放在一起。
4. **信任靠近决策**：来源等级和核验时间不能只藏在页面底部。
5. **渐进披露**：卡片提供判断所需的最少信息，详情承载背景与证据。
6. **真实功能优先**：未形成闭环的订阅不作为全局第一操作。
7. **结构支持扩展**：今日简报、历史简报和单条资讯未来可以拥有稳定地址。

## 3. 产品层级

### 一级入口

| 入口 | 用户问题 | MVP 形态 |
| --- | --- | --- |
| 今日简报 | 今天最重要的变化是什么？ | 首页核心内容 |
| 历史简报 | 最近几天发生了什么？ | 后续独立页面或日期视图 |
| 核验方法 | 这些判断为什么可信？ | 首页摘要 + 完整说明页 |
| 项目复盘 | 这个产品如何被设计出来？ | 作品集独立页面 |

### 内容对象

| 对象 | 作用 | 关系 |
| --- | --- | --- |
| 每日简报 | 某一天的内容集合 | 包含 3–8 条资讯 |
| 今日必读 | 当天优先级最高的资讯 | 每日简报中最多 1 条 |
| 资讯条目 | 一次产品或行业变化 | 属于一个或多个主题 |
| 信源 | 支撑事实和核验等级 | 一条资讯至少一个精确来源 |
| 主题 | 帮助浏览和筛选 | 模型、产品、商业、政策、安全、开发者 |
| 行动 | 帮助用户决定下一步 | 深入阅读、收藏、关注、迁移、评估等 |

## 5. 各模块内容职责

### 5.1 顶部导航

建议导航：

- 今日简报
- 历史简报
- 核验方法
- 项目复盘

右侧主要操作在真实收藏功能完成前使用“查看今日重点”；真实订阅完成后再改为“订阅简报”。

移动端需要折叠导航，但必须保留“今日简报”和菜单入口。

### 5.2 价值首屏

只承担四项职责：

- 明确服务对象：中文产品从业者；
- 明确使用结果：看懂 AI 变化对产品意味着什么；
- 明确所需时间：每天 5 分钟；
- 给出一个主要行动：阅读今日简报。

首屏不再强调固定 7 条，不使用“全天候”等无法持续证明的承诺。

### 5.3 今日概览

以轻量状态条呈现：

- 内容覆盖时间，例如“过去 24 小时”；
- 入选资讯数量；
- 今日重点主题；
- 最后核验时间；
- AI 辅助、人工复核说明。

所有数字必须从实际数据生成，不能手工长期写死。

### 5.4 今日必读

每天最多一条，占据主要视觉层级。至少展示：

- 标题和一句话事实；
- 为什么今天最重要；
- 影响对象；
- 建议行动；
- 精确来源和核验时间；
- “查看完整判断”和“查看原文”两个不同出口。

如果当天没有明显的第一优先级，不强行设置今日必读，可以直接进入简报列表。

### 5.5 今日简报

除今日必读之外的 2–7 条资讯。信息层级：

1. 来源、时间、状态和可信度；
2. 标题；
3. 一句话事实摘要；
4. 为什么重要；
5. 影响对象和主题；
6. 查看判断与查看原文。

筛选器放在列表标题下方，不占据首屏。

### 5.6 近 7 天信号

该模块属于 P2。只有在积累至少 7 天结构化数据后才上线，避免用少量静态样本制造趋势。

未来可以展示：

- 热门主题变化；
- 高频公司；
- 产品发布、政策、安全等内容占比；
- 持续跟踪中的事件。

### 5.7 我们如何工作

将现有“信源矩阵”和“核验方法”合并，减少重复。首页只保留简版流程：

发现 → 筛选 → AI 辅助提炼 → 人工核验 → 发布与纠错。

同时显示：

- A/B/C 信源等级；
- 事实与判断如何区分；
- 为什么不会自动发布未经核验的摘要；
- 完整方法说明入口。

### 5.8 订阅与反馈

在真实订阅功能完成前：

- 移除或降级全局“订阅早报”按钮；
- 页面末尾改为“这个判断有帮助吗？”或“反馈问题”；
- 明确演示功能，不能伪装成已完成服务。

真实订阅上线后，再把订阅恢复为主要留存入口。

### 5.9 页脚与项目入口

保留品牌口号，并加入：

- 核验方法；
- 项目复盘；
- 数据与隐私说明；
- 纠错入口；
- GitHub 或作品集入口。

## 6. 分类与标签层级

本阶段确定结构，具体交互在 F01/F02 实现。

### 一级筛选：主题

- 模型与技术
- 产品发布
- 商业与公司
- 政策与治理
- 安全
- 开发者提醒

### 二级筛选

- 地区：中国、海外、全球
- 时间：今天、近 7 天、近 30 天
- 信源：官方、多源核验

### 描述性标签

公司名、产品名、模型名和影响对象作为标签，不与一级主题混用。

## 7. 核心用户路径

### 路径 A：5 分钟日常扫描

1. 从首屏确认今日更新时间；
2. 阅读“今日必读”；
3. 扫描其余资讯的标题和“为什么重要”；
4. 打开与自己相关的完整判断；
5. 选择查看原文、收藏或结束浏览。

### 路径 B：验证可信度

1. 从卡片查看来源等级和状态；
2. 打开完整判断；
3. 检查核验时间和判定理由；
4. 进入精确原文复核；
5. 发现问题时提交纠错反馈。

### 路径 C：查找特定主题

1. 进入今日简报或历史简报；
2. 选择主题并叠加地区或时间；
3. 使用搜索进一步缩小范围；
4. 打开目标资讯；
5. 清除条件或返回结果列表。

### 路径 D：作品集评审

1. 面试官从首页理解真实产品价值；
2. 体验一个完整资讯判断；
3. 查看核验和 AI 协作机制；
4. 进入项目复盘；
5. 查看问题定义、取舍、测试和迭代结果。

## 8. 页面地址规划

MVP 可先保持静态实现，但命名应支持后续扩展：

| 页面 | 建议地址 | 说明 |
| --- | --- | --- |
| 今日简报 | `/` | 默认首页 |
| 历史简报 | `/archive/` | 按日期浏览 |
| 单条资讯 | `/briefs/{slug}/` | 可分享、可回访 |
| 核验方法 | `/method/` | 完整编辑与核验标准 |
| 项目复盘 | `/case-study/` | 面向作品集评审者 |

在独立页面尚未实现前，可以先使用单页锚点，但导航命名保持一致。

## 9. 模块增删与合并决策

| 当前模块 | 决策 | 原因 |
| --- | --- | --- |
| 品牌首屏 | 保留并重写 | 视觉识别强，但定位表达需更新 |
| 首屏固定数字 | 改为动态今日概览 | 避免长期写死或无法证明 |
| 资讯网格 | 拆成今日必读 + 今日简报 | 建立优先级，减少判断成本 |
| 全球/中国/产品/产业筛选 | 重构 | 混合了地区和主题维度 |
| 信源矩阵 | 与核验方法合并 | 内容职责重叠 |
| 核验方法 | 保留并前置关键信息 | 信任证据应靠近内容 |
| 顶部订阅 | 暂时降级 | 当前只有演示交互 |
| 近 7 天趋势 | 延后新增 | 需要足够的历史数据支撑 |
| 项目复盘入口 | 新增 | 支撑产品经理作品集表达 |

## 10. 首版实现范围

第 2 步只锁定结构，不提前填充后续尚未定义的数据字段。后续按以下顺序落地：

1. C01/C02 定义并实现新闻卡片与详情；
2. F01/F02 实现分类和搜索；
3. T01/T02 实现信源与透明机制；
4. D01/D02 将数据与界面解耦并建立更新流程；
5. U01/U02/U03 增加收藏、反馈和历史简报；
6. 数据足够后再上线近 7 天趋势。

这样可以避免页面先出现没有真实内容或无法工作的空模块。

## 11. 信息架构验收标准

- 新用户可以在首屏识别目标用户、使用结果、所需时间和主要行动。
- 页面在今日简报之前只保留完成任务所需的信息，不堆叠品牌说明。
- 每个模块只回答一个主要问题，没有重复解释核验机制。
- 今日必读与普通资讯具有明确层级。
- 主题、地区、时间和描述性标签在结构上彼此分离。
- 所有全局操作必须对应真实能力；演示功能明确标注或降级。
- 核心路径在桌面和移动端均不依赖悬停操作。
- 页面结构能够支持历史简报、单条资讯和项目复盘的后续扩展。

## 12. 本阶段决策记录

1. 首页主任务确定为“完成今日 AI 产品变化扫描”。
2. 首页内容顺序确定为“价值 → 概览 → 今日必读 → 简报 → 方法 → 留存”。
3. 资讯从完全平铺改为一条重点加若干普通条目。
4. 信源矩阵和核验方法合并为“我们如何工作”。
5. 订阅在形成真实闭环前不再占据全局主要位置。
6. 趋势模块等待真实历史数据，不在静态样本上制造结论。
7. 新增历史简报、核验方法和项目复盘三个可扩展入口。
