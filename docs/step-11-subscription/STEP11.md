# 第 11 步：真实订阅闭环

## 决策

移除无法兑现的邮箱演示表单，改为无需后台、无需收集个人信息的 RSS 订阅。订阅频率不再承诺“每天 9:30”，而是以人工审核后的实际发布时间为准。

## 实现

- `scripts/build-data.mjs` 在生成网页数据时同步生成标准 RSS 2.0 文件 `feed.xml`。
- RSS 只读取 `data/news.json` 中已经人工批准的正式资讯。
- 每条订阅内容包含中文标题、摘要、产品价值判断、发布日期、来源与精确原文链接。
- 页面 `<head>` 声明 RSS 自动发现链接。
- 订阅弹窗提供“打开订阅源”和“复制订阅地址”两种操作。
- 复制失败时直接显示完整地址，不产生虚假的成功提示。

## 验收标准

- RSS 文件能够作为合法 XML 解析。
- RSS 条目数量与正式资讯数量一致。
- 新资讯通过审核脚本发布后，RSS 自动同步更新。
- 页面不再展示虚假邮箱提交成功状态。
- 用户无需提供邮箱或其他个人信息。

## 产品取舍

RSS 的大众认知度低于邮件，但在没有服务端、隐私协议和邮件发送服务的静态 MVP 中，它是可真正兑现、成本可控且不误导用户的订阅方式。后续若验证出足够订阅需求，再接入合规邮件服务。
