# 第 15 步：无障碍优化与键盘验收

## 审查范围

面向使用键盘、放大显示或辅助技术的读者，检查首页浏览、跳过导航、打开资讯详情、收藏、反馈和关闭弹窗的核心路径。

## 主要修复

1. 增加“跳到主要内容”链接，并让主内容可接收程序化焦点。
2. 移除资讯卡片外层的伪按钮语义；保留清晰的“查看完整判断”原生按钮，避免可交互元素嵌套。
3. 为详情按钮补充弹窗提示和完整资讯名称；外部链接说明会在新窗口打开。
4. 收藏与反馈导致内容重绘后，将焦点恢复到对应控件。
5. 详情弹窗关闭后，将焦点返回原资讯的“查看完整判断”按钮。
6. 为三个弹窗补充可访问名称，为详情侧栏补充真实标题层级。
7. 为所有常用交互补充统一、清晰的 `:focus-visible` 样式；弹窗关闭按钮扩大至 44 × 44px。
8. 将品牌粉色和强调粉色加深，小号辅助文字统一使用高对比度文本色。
   - 强调色 `#c9266b` 在页面底色上的对比度约为 5.12:1。
   - 品牌色 `#cf286d` 与白色的对比度约为 4.87:1。
9. 在减少动态效果偏好下，将动画与过渡压缩到近乎静止。

## 自动验收结果

`scripts/check-accessibility.mjs` 使用 Edge DevTools Protocol 执行实际键盘路径并输出 `keyboard-audit.json`。

| 步骤 | 结果 | 证据 |
| --- | --- | --- |
| 01 首页结构 | 通过 | `lang=zh-CN`，唯一主内容区，0 个无名称控件 |
| 02 跳过导航 | 通过 | 第一次 Tab 聚焦跳过链接，Enter 后焦点到 `main-content` |
| 03 资讯入口 | 通过 | “查看完整判断”有可见焦点且无嵌套交互控件 |
| 04 详情弹窗 | 通过 | Enter 打开，关闭按钮自动获得焦点，弹窗具备标题关联 |
| 05 收藏与反馈 | 通过 | 操作后 `aria-pressed` 更新，焦点保留在原控件 |
| 06 关闭与返回 | 通过 | Esc 关闭后焦点返回原“查看完整判断”按钮 |

静态审计还确认：重复 ID 为 0、缺失图片替代文本为 0、嵌套交互控件为 0。

## 证据边界

本步骤验证了 DOM 语义、键盘操作、焦点路径、可见焦点、目标尺寸和关键颜色对比度，但没有使用 NVDA、JAWS 或 VoiceOver 进行真人屏幕阅读器朗读测试，因此不声明完整 WCAG 合规。
